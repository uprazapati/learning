Cloud Computing vs. Supercomputing

Two different ways to build a very large computing system, built for two different jobs. From DDIA, Chapter 1 ("Cloud Computing Versus Supercomputing").

cloud computing supercomputing (HPC)
Cloud computingSupercomputing (HPC)
Online services, business systems — serve user requests with high availability Heavy scientific computation — weather/climate models, molecular dynamics, optimization problems
Can't stop the cluster — services must keep running continuously Checkpoints progress to disk; on failure, stops everything, fixes the node, resumes from the last checkpoint
Network/machines shared by mutually untrusting organizations — needs real security: VMs for isolation, encryption, authentication Nodes talk via shared memory and RDMA (fast, low latency) — assumes everyone on the system already trusts each other
Datacenter networks: standard IP/Ethernet, arranged for high bandwidth across the whole network Specialized network shapes (meshes, toruses) tuned for each job's specific, known communication pattern
Nodes can be spread across different geographic regions Nodes assumed to all sit close together
Why this is worth knowing — big analytical systems sometimes borrow HPC techniques, so it's useful to recognize them. But these notes are mainly about services that must stay continuously available — which is the cloud column, not the HPC one.
